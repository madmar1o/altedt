## Почему MCP показывал error (2026-10-18)

MCP запускался как `docker exec -i swarm-ctxsum python /tool/mcp_server.py`, то есть его
stdio-канал жил **внутри контейнера сервиса**. Мой `docker restart swarm-ctxsum` (правка
`keep_alive`) убил все exec-сессии — у всех подключённых агентов MCP стал error, хотя сам
сервис был здоров.

Лечение (проверено): отдельный контейнер `swarm-ctxsum-mcp`, общение по HTTP
(`CTXSUM_URL=http://ctxsum:8080`). Контейнер живёт как exec-хост (`sleep infinity`):
`mcp_server.py` читает stdin и выходит при закрытом stdin, поэтому на постоянном запуске
он уходил бы в рестарт — клиент поднимает процесс сам.
Тест: `docker restart swarm-ctxsum` → MCP-контейнер жив, рукопожатие и tools/call проходят.

Правило на будущее: **MCP-обёртки не держать внутри перезапускаемых сервисных контейнеров.**

## Docker MCP и системный промпт (2026-10-18)

**Gateway не подошёл — и это проверено, а не предположено.** `docker mcp catalog create X
--server docker://localhost/ctxsum-mcp:1` → «image is not a self-describing image».
То же самое для официального `mcp/fetch` — значит `docker://` ждёт OCI-артефакт из реестра
MCP, локально его не получить; `docker mcp server init` умеет только Go.
Реализовано вместо этого **MCP по HTTP в собственном сервисе**: `POST /mcp`, JSON-RPC без
сессий, общая логика с `mcp_server.py` через importlib. Клиенту нужна одна строка:
`{type:'remote', url:'http://127.0.0.1:11436/mcp'}` — без `docker exec`, переживает рестарт
сервиса, работает в любом MCP-клиенте.

**Функция в системном промпте каждой модели**: создан глобальный
`~/.config/opencode/AGENTS.md` (читается как инструкции для всех агентов — подтверждено
загрузкой в сессию) + указание в `agents/orchestrator.md` и `agents/1c-tester.md`.

**Честное ограничение сжатия**: сжать контекст внутри уже идущей сессии нельзя —
сводка пишется в `session-handoff.md`, но в контекст подхватывает только **новая** сессия.
Правило в `AGENTS.md` велит вызывать сжатие заранее, пока контекст ещё не раздут.

### Переход solcache на bge-m3 (768 → 1024)

- `solcache.ps1`: `$EmbedModel`/`$EmbedDim` вынесены в переменные с переопределением через
  `$env:SOLCACHE_EMBED_MODEL` / `$env:SOLCACHE_EMBED_DIM` — смена модели больше не требует
  правки файла. Размерность в `Ensure-Collection` и в выводе `ensure` считается из неё же.
- `Get-Embedding` **проверяет размерность** и падает с внятным сообщением вместо 400 от Qdrant.
- Новый скрипт `solcache-remigrate.ps1` пересчитывает вектора, сохраняя id, `success/fail`
  и `last_used`. Без `-Confirm` — dry-run. Бэкапы пишет в `~/.config/opencode/infra/solcache-backup/`.
- Миграция 51 точки прошла успешно, данные не потеряны.

**Ловушка, которую я сам же и создал, а потом поймал.** `Invoke-RestMethod` в PS 5.1
декодирует `application/json` как ISO-8859-1, кириллица приходит как `Ð¿Ñ€Ð¸Ð²ÐµÑ`.
Скрипт миграции прочитал так Qdrant и записал обратно — **порча была напечатана в хранилище
навсегда**: 10 289 кириллических символов превратились в 0 кириллиц + 10 324 символа Latin-1.
Вектора при этом остались рабочими (bge-m3 устойчив к ломочке), recall даже выдавал верные
ответы — то есть поломка была полностью невидима снаружи.

Правильное чтение — только сырыми байтами, их теперь делает `Get-Utf8Json` в скрипте:
```powershell
curl.exe -s -X POST $uri -H "Content-Type: application/json" --data-binary "@req.json" -o res.json
[Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes("res.json")) | ConvertFrom-Json
```
Откат был возможен только потому, что чистый бэкап сняли **до** первой миграции.

**Проверять надо байтами, а не глазами.** Консоль гасит кириллицу (ACP windows-1251), поэтому
счёт по «?» и по вхождению кириллицы делается на файле, сохранённом через
`[IO.File]::WriteAllText(..., UTF8Encoding $false)`. Отдельно: `[Console]::OutputEncoding`
в начале команды чинит вывод, но не отменяет проверку.
