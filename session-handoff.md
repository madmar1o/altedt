# Сводка сессии — AltEDT

**Полное состояние мира — в `session-notes.md` (коммит `ef33a97`).** Этот файл — короткая
указательница, чтобы новая сессия не тратила токены на выяснение «с чего начать».

## Почему файл ручной

`ctxsum.compact_session` с `dir` выбирает **самую большую** сессию в каталоге, а не текущую.
Проверено 2026-10-18: на запрос вернул сводку старой сессии `ses_eb6fd4193…` (770 сообщений)
с «следующим шагом» — этап 2, который закрыт коммитом `e42e292`. Автогенерация здесь даёт
правдоподобный, но устаревший текст, что хуже отсутствия файла. Если сжатие всё же нужно —
генерировать на конкретной сессии и **вычитывать результат**, прежде чем записывать.

## Где мы

Проектные этапы **0–8 закрыты** и закоммичены в `alt-edt/` (дочерний репозиторий, ветка `main`,
на 8 коммитов впереди `upstream/main`, пуша не было). Тесты: 2047 passing (vscode) +
253 passing (node), 0 failing, коммит `37534e0`.

Не закрыт только **этап 9** — визуальный дизайнер форм, сознательно отложенный последок.

Инфраструктура роя (живёт в `~/.config`, не в этом репозитории) работает: контейнеры
`swarm-ctxsum`, `swarm-ctxsum-mcp`, `swarm-ollama`, `solcache-redis`, `solcache-qdrant` — все
healthy. Сжатие контекста включено, порог 60 000 симв.

## Следующий шаг

Одно из двух, на выбор владельца:

1. **Этап 9 — дизайнер форм.** Разбор форка уже есть в `session-notes.md`; нужны операции
   структуры (add/move/remove элементов) поверх webview. Перед стартом имеет смысл
   `solcache recall` по «форма элемент webview add move remove» — в кэше этого нет.
2. **Слой 3 (хуки ctxsum).** Отложен осознанно: Claude Code на машине **не установлен**
   (проверено 2026-10-18), а у OpenCode нет своего `PreCompact`. У хуков нет потребителя;
   рабочая точка входа — MCP `ctxsum.compact_session`.

## Экономия токенов — обязательный порядок работы

1. Прочитать этот файл и `session-notes.md`. Не пересказывать их в ответе.
2. **Перед** любым диспатчем воркера — `solcache get`, затем `recall` (порог 0.6).
   Попадание = 0 токенов, диспатч не делаем.
3. **После** проверки результата по реальности — `remember`. Без проверки не писать.
4. Воркерам — только бесплатные/локальные модели. Отказ admission (429/5xx) ≠ провал задачи:
   requeue + backoff + failover; с 5 попыток — делать самому.
5. Контекст: `ctxsum.compact_session` вызывать **до** того, как он раздулся, а не когда
   упёрлись. Порог можно опустить: `ctxctl.ps1 on -Threshold 40000`.

## Ловушки этого окружения (проверены, а не пересказаны)

- **PS 5.1 + ACP windows-1251**: консоль гасит кириллицу. Проверять байтами, а не глазами.
- **`.ps1` обязаны быть с BOM.** `solcache.ps1` BOM **не имел** вопреки заметкам — поправлено
  2026-10-18. После любой правки: `Parser.ParseFile` + `EF BB BF` первыми байтами.
- **`Invoke-RestMethod` декодирует `application/json` как ISO-8859-1.** Записать такую строку
  обратно = напечатать порчу в Qdrant навсегда. Чтение — только сырыми байтами через curl
  `--data-binary @file`. Подробности в `session-notes.md`, раздел про bge-m3.
- **`curl -d` в PowerShell режет кавычки** — тело только `--data-binary "@file"`.
- **VRAM 8 ГиБ**: `qwen3:8b` (5,86) + `prism-coder:2b` (~3) не помещаются вместе (8,9 ГиБ) —
  вытеснение заставляет платить холодную загрузку (~13 с) каждый раз. `bge-m3` (0,62) с qwen
  уживаются.
- **MCP-обёртки не держать внутри перезапускаемых сервисных контейнеров.**
- **Правка bind-mount файла не перезапускает процесс** — нужен `docker restart`.
